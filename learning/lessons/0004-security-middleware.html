Цель: заполнить три пропуска в auth.handlers.ts, чтобы GET /api/auth/me отвечал 200 с User или 401.

Рабочий пример: ключ в заголовке вместо cookie

Тот же механизм на соседней задаче. Клиент присылает x-api-key, middleware находит клиента и кладёт его в Context, endpoint /whoami его возвращает. Пример запускался на rc.108, tsc без ошибок.

// 1. Что middleware кладёт в Context
class CurrentClient extends Context.Service<
  CurrentClient,
  { readonly name: string }
>()('example/CurrentClient') {}

class UnauthorizedError extends Schema.Error<UnauthorizedError>(
  'UnauthorizedError',
)({ message: Schema.String }, { httpApiStatus: 401 }) {}

// 2. Объявить middleware: откуда credential, что даёт, чем падает
class ApiKeyAuth extends HttpApiMiddleware.Service<
  ApiKeyAuth,
  { provides: CurrentClient }
>()('example/ApiKeyAuth', {
  security: { apiKey: HttpApiSecurity.apiKey({ key: 'x-api-key', in: 'header' }) },
  error: UnauthorizedError,
}) {}

// 3. Подключить middleware к endpoint
const api = HttpApi.make('example').add(
  HttpApiGroup.make('clients').add(
    HttpApiEndpoint.get('whoami', '/whoami', {
      success: Schema.Struct({ name: Schema.String }),
    }).middleware(ApiKeyAuth),
  ),
);

// 4. Реализовать middleware: проверить credential и положить клиента в Context
const knownKeys = new Map([['secret-123', 'mobile-app']]);
const ApiKeyAuthLive = Layer.succeed(ApiKeyAuth, {
  apiKey: (httpEffect, { credential }) =>
    Effect.gen(function* () {
      const name = knownKeys.get(Redacted.value(credential));
      if (name === undefined) {
        return yield* new UnauthorizedError({ message: 'Unknown API key' });
      }
      return yield* httpEffect.pipe(Effect.provideService(CurrentClient, { name }));
    }),
});

// 5. Handler берёт клиента из Context, а не читает заголовок сам
const ClientsLive = HttpApiBuilder.group(api, 'clients', (handlers) =>
  handlers.handle('whoami', () =>
    Effect.gen(function* () {
      const client = yield* CurrentClient;
      return { name: client.name };
    }),
  ),
);

// Три запроса: без ключа, с чужим ключом, с верным
for (const key of [undefined, 'wrong', 'secret-123']) { … }

  1. Что middleware кладёт в Context. CurrentClient — обычный Context.Service. В проекте это CurrentSession со значением AuthenticatedSession.
  2. Объявить middleware. security говорит, откуда взять credential; provides — какой сервис получит endpoint; error — какими HTTP-ошибками middleware может ответить.
  3. Подключить к endpoint. .middleware(ApiKeyAuth) на endpoint. Без него handler попросит CurrentClient, а дать его некому.
  4. Реализовать middleware. Функция получает httpEffect — ещё не запущенный handler — и credential. Отказ: вернуть ошибку, handler не запустится. Успех: httpEffect.pipe(Effect.provideService(…)).
  5. Handler читает Context. yield* CurrentClient. Заголовок он не разбирает.
Убрали .middleware(ApiKeyAuth) с endpoint. Что будет при компиляции и при запросе с верным ключом?

tsc падает, но сообщение неочевидное: HttpRouter.toWebHandler «Expected 2 arguments, but got 1». Требование CurrentClient не закрыто, и обработчику нужен дополнительный Context. Если запустить без проверки типов, любой запрос даст 500: Service not found: example/CurrentClient. Middleware не вызывался, ключ не проверялся.
