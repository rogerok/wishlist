Signup: три решения, которые держат код целым

AuthService.signup создаёт User, Password Credential и Session за один запрос. Ниже три решения: если отменить любое из них, сломается что-то наблюдаемое.

auth.service.tsКарта: путь запроса

1. Hash и token считаются до транзакции

Чтоauth.service.ts:96–99

const passwordHash = yield* hasher.hash(Redacted.make(password));
const { credential, digest } = yield* tokenGenerator.generate;

const { user, expiresAt } = yield* db.withTransaction(
  // ...только запросы к БД

ПочемуТранзакция занимает соединение из пула от BEGIN до COMMIT. Один scrypt с N=2^17 требует около 128 MiB и заметное время. Если считать хеш внутри транзакции, то при 10 одновременных регистрациях 10 соединений простаивают, пока идёт scrypt. Остальные запросы, даже GET /api/users, ждут свободное соединение.

ЦенаНет. Hash не зависит от данных в БД, поэтому его можно посчитать заранее.

2. Три INSERT в одной транзакции

Чтоauth.service.ts:99–121: usersRepo.create → passwordRepo.create → sessionRepo.create внутри db.withTransaction.

stateDiagram-v2
  [*] --> BEGIN
  BEGIN --> user: INSERT users
  user --> credential: INSERT password_credentials
  credential --> session: INSERT sessions
  session --> COMMIT
  user --> ROLLBACK: ошибка
  credential --> ROLLBACK: ошибка
  session --> ROLLBACK: ошибка
  COMMIT --> [*]: 3 строки
  ROLLBACK --> [*]: 0 строк

ПочемуБез транзакции сбой на втором INSERT оставит user без пароля. Email уже занят уникальным индексом, а войти нельзя: повторный signup получит 409. Транзакция даёт два исхода: 3 строки или 0.

ЦенаСоединение занято на три INSERT. Это миллисекунды, потому что scrypt вынесен наружу (решение 1).

3. Двенадцать внутренних ошибок сводятся к трём

Чтоauth.service.ts:34–67, mapSignupError:

Match.value(error).pipe(
  Match.tag('UserEmailAlreadyExists', (cause) => new AuthEmailAlreadyExistsError({ cause })),
  Match.tag('PasswordHashOverloadedError', 'SecurePrimitiveUnavailableError',
    (cause) => new AuthUnavailableError({ cause })),
  // ...повреждённые записи и дубликаты → AuthInternalError
  Match.exhaustive,
);

ПочемуHandler знает три исхода: 409, 503, 500 (карта ошибок). Match.exhaustive превращает новую необработанную ошибку репозитория в ошибку компиляции именно здесь. Без него новая ошибка молча станет дефектом и 500 без понятного лога.

ЦенаКаждая новая ошибка репозитория требует строки в mapSignupError. Это и есть цель: решение принимается явно.

Собери signup

Расставь строки так, чтобы scrypt не держал соединение, а в БД не попал ни пароль, ни сам token. Две строки лишние.

  • const passwordHash = yield* hasher.hash(Redacted.make(password));
    const { credential, digest } = yield* tokenGenerator.generate;
  • const { user, expiresAt } = yield* db.withTransaction(Effect.gen(function* () {
  • const user = yield* usersRepo.create({ email, firstName, middleName, lastName });
  • yield* passwordRepo.create(user.id, passwordHash);
  • const session = yield* sessionRepo.create(user.id, digest, expiresAt);
  • return { user, expiresAt: session.expiresAt }; }));
  • }).pipe(Effect.mapError(mapSignupError));
  • yield* passwordRepo.create(user.id, password);
  • const session = yield* sessionRepo.create(user.id, credential, expiresAt);

Пароль и session можно записать в любом порядке: обоим нужен только user.id. Лишние строки сохраняют в БД секрет в открытом виде: утечка таблицы отдала бы пароли или готовые cookie.

Расчёт expiresAt через Clock убран из задачи ради краткости.

Вопросы на вспоминание

Ответь через 2–3 дня, не открывая код. Агент покажет их в начале сессии.

Пришло 20 signup одновременно, а hash перенесли внутрь транзакции. Что случится с остальными запросами к API?

Соединения пула заняты ожиданием scrypt, и запросы, которым нужна БД, ждут свободное соединение. Решение 1.

sessionRepo.create упал. Какие строки этого signup останутся в БД?

Никакие: транзакция откатит user и password_credentials. Клиент получит 500 или 503, cookie не выставляется. Решение 2.

В UsersRepository добавили ошибку UserEmailTooLong. Где и как ты об этом узнаешь?

При check-types: Match.exhaustive в mapSignupError не скомпилируется, пока ошибка не получит ветку. Решение 3.
