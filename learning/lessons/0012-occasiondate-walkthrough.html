Пройдём обход списка по сортировке occasionDate запрос за запросом и посмотрим, что на каждом шаге делает каждое поле пресета.

Урок 0011: пагинация целиком design.md, решение 5

1. Какой порядок нужен

Пользователь хочет видеть сначала ближайшие праздники, потом прошедшие, потом Wishlist без даты. Пусть сегодня 2026-10-18:

Wishlistдатагруппадней от сегодняместо
U12026-10-180, будущая01
U22026-12-310, будущая742
UL, UH2027-01-150, будущая893, 4 (решает id)
P12026-10-171, прошедшая15
P22026-05-011, прошедшая1706
Nнет207

Обе вычисленные колонки зависят от «сегодня». Это «сегодня» и есть asOf (англ. «по состоянию на»).

2. Пресет по полям

Пресет из apps/api/src/infra/pagination/keyset.test.ts, сокращённо:

const occasionDate = {
  direction: 'asc',
  key: [
    keyPart({ /* occasion_date */ rule: (date, { asOf }) => CASE WHEN date IS NULL THEN 2 WHEN date >= asOf THEN 0 ELSE 1 END }), // группа
    keyPart({ /* occasion_date */ rule: (date, { asOf }) => CASE WHEN date IS NULL THEN 0 WHEN date >= asOf THEN date - asOf ELSE asOf - date END }), // дни
    keyPart({ /* id */ }),
  ],
  params: {
    first: Effect.gen(…DateTime.now → начало дня → '2026-10-18'),  // ① asOf для первой страницы
    types: { asOf: 'date' },                                         // ② к какому SQL-типу приводить asOf
    fromCursor: (cursor) => ({ asOf: cursor.asOf }),                 // ③ asOf для следующих страниц
  },
  cursorOf: (row, { asOf }) => ({ ...row, asOf }),                   // ④ что положить в курсор
};

Поля ①–④ отвечают на два вопроса: откуда взять asOf и как он попадёт в SQL.

① first

Курсора нет, это первая страница. Берём дату из Clock: { asOf: '2026-10-18' }.

④ cursorOf

Страница готова. Кладём asOf в курсор рядом с датой и id последней строки.

③ fromCursor

Клиент вернул курсор. Достаём из него тот же asOf, Clock не читаем.

② types

Модуль знает значение '2026-10-18', но SQL нужен тип. types говорит: date. Модуль строит cast($1 as date) и отдаёт его в rule.

③ и ④ работают в паре: ④ записывает asOf в курсор, ③ читает его обратно на следующем запросе. Так дата отсчёта переживает переход между страницами, даже если между ними наступила полночь.

3. Симулятор обхода

Нажимай «Запросить страницу» и смотри, откуда берётся asOf, какое условие уходит в базу и какие строки получает клиент. Между запросами можно перевести часы.

отдано клиенту лишняя строка: признак, что есть продолжение отрезано условием «после курсора»

4. Проверь себя

Выбери «Полночь посреди обхода», режим «заново из часов», limit 1. Запроси первую страницу в 23:59, переведи часы, поставь limit 2 и запроси вторую.

Какой Wishlist пропадёт и почему ошибки не будет?

Пропадёт Y (2026-12-31). Вторая страница считает asOf = 2026-10-19, и X из курсора становится прошедшим: тройка курсора (1, 1, X). У Y тройка (0, 74, Y), она меньше курсора, и WHERE её отрезает. Запрос корректен, база вернёт P без ошибок. В режиме «из курсора» тройка X остаётся (0, 0, X), и Y приходит.
