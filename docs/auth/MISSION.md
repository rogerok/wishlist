# Mission: PostgreSQL session authentication with Effect

## Why

Самостоятельно выполнить задание ментора: реализовать безопасную серверную аутентификацию на PostgreSQL-сессиях в существующем wishlist API и уметь объяснить каждое решение без помощи AI.

## Success looks like

- Самостоятельно реализовать `/api/auth/signup`, `/api/auth/login`, `/api/auth/me` и `/api/auth/logout` в текущей Effect-архитектуре.
- Объяснить, какие состояния хранят User, Password Credential и Session, и какие события меняют каждое состояние.
- Сохранить типизированные ошибки, явные зависимости, Layer composition и транзакционную границу signup.
- Доказать поведение интеграционными тестами PostgreSQL, HttpApi-тестами и реальным cookie-jar сценарием.
- Отличать безопасный минимальный срез от production-hardening и реализовывать backlog по риску.

## Constraints

- Backend-код пишет владелец проекта; агент объясняет, даёт упражнения, проверяет гипотезы и помогает при конкретных затруднениях.
- Основной стек: strict TypeScript ESM, Node.js, Effect 4 RC, Effect Platform, PostgreSQL, Kysely и Effect SQL.
- Обучение идёт маленькими вертикальными шагами: состояние → операция → ошибки → проверка.
- Материалы должны быть на русском либо сопровождаться точным указанием, что читать в англоязычном источнике.

## Out of scope

- JWT вместо согласованных серверных Sessions.
- OAuth, OIDC, MFA и WebAuthn до завершения базовой Session-аутентификации.
- Полное копирование чужой auth-реализации без адаптации к установленной версии Effect и локальным инвариантам.
- Генерация backend-реализации агентом вместо самостоятельной практики.
