# Tasks

Код приложения, тесты и временный smoke-сценарий пишет владелец проекта.
Агент корректирует план и помогает разбирать результаты проверок, не реализуя задачи за владельца.

После успешного сервиса выдавать истекающую cookie. Обновить все существующие подмены `AuthService`, не меняя `SessionAuthentication`. В новом `auth.logout.test.ts` создать две Session User A и одну User B; проверить точное удаление S1, неизменные поля S2/S3, `204` и пустое тело. Проверка: `pnpm --filter @wishlist/api test src/modules/auth/handlers/auth.logout.test.ts --no-file-parallelism` и `pnpm --filter @wishlist/api check-types`.

- [x] 1.2 Реализовать и проверить сценарии «Отсутствующая cookie», «Повреждённая cookie», «Неизвестная Session», «Истекшая Session», «Повторный logout», «Удаление существующей истекшей Session», «Истечение cookie без cookie в запросе», «Истечение повреждённой cookie», «Истечение cookie неизвестной Session» и «Истечение cookie истекшей Session». ## 2. Технические отказы logout

- [x] 2.1 Реализовать и проверить HTTP-ответ для сценария «PostgreSQL недоступен до запроса»: сопоставить retryable SQL-ошибку через существующий `mapTechnicalError`, перевести её в `503` через `makeTechnicalErrorHandler` с операцией logout. Тест использует настоящие исходные строки S1/S2 и подменяет отказ repository до выполнения SQL; проверить `application/problem+json`, `SERVICE_UNAVAILABLE`, `instance: /api/auth/logout`, корректный `errorId`, отсутствие `Set-Cookie` для `wishlist_session` и неизменные строки через контрольное подключение. Не выдавать эту подмену за настоящую недоступность PostgreSQL: реальную границу проверяет задача 3.2. Проверка: `pnpm --filter @wishlist/api test src/modules/auth/handlers/auth.logout.test.ts --no-file-parallelism` и `pnpm --filter @wishlist/api check-types`.

- [x] 2.2 Реализовать и проверить сценарии «Необратимая ошибка удаления» и «Непредвиденное исключение»: использовать существующий перевод в `AuthInternalError` и общий `DefectBoundaryMiddleware`.
