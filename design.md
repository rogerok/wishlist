# Wishlist — «С любовью»

Единая визуальная система прототипа в `docs/design/`. Предыдущие направления Garden, Parcel collection и разреженный Personal album больше не являются ориентиром. Не возвращать шалфейные и розовые панели, пастельные карточки, банты, наклонные бирки, огромные даты и газетные заголовки списков.

## Идея

Личный сервис для желаний и подарков, а не магазин, рабочая панель или редакционный лендинг. Человечность передают реальные желания, понятные действия и тёплый красный акцент. Праздничность не означает раскрашивать все поверхности или добавлять лозунги.

- Hallmark: custom / personal application; структура Compact collection.
- Навигация: верхняя компактная шапка. На широком экране пункты идут рядом с логотипом, а аккаунт — справа; до 640 px пункты занимают отдельную строку. Боковой панели нет.
- Коллекция: одна колонка с тонкими разделителями. Название, описание и метаданные образуют одну строку списка, высота зависит от содержания. Нет искусственной минимальной высоты и пустой колонки под дату.
- Дата и доступ находятся рядом под описанием и при необходимости переносятся. Дата размечена через `time`; при отсутствии — «Без даты», без декоративного числа или прочерка.
- Вся строка открывает список. У неё один настоящий link, а стрелка — ненажимаемый указатель. Клавиатурный фокус обводит всю строку.
- Желания: открытые секции, без фоновых карточек; две колонки с 640 px, одна на телефоне. Сначала название, затем приоритет и комментарий. Цена и внешняя ссылка находятся рядом; статус брони и действие — внизу. Между рядами нет дополнительного пустого промежутка сверх внутренних отступов. Нет изображений товаров до соответствующего продуктового этапа.
- Вход и регистрация: одна форма шириной до 416 px, без рекламной половины, плакатного заголовка и декоративных иллюстраций.

## Палитра

Светлая тема: тёплый белый фон без бежевой заливки, тёмный чернильный текст и чистый красный акцент. Не возвращать пыльную терракоту и кирпичные оттенки. Красный используется для бренда, главного действия и высокого приоритета; ошибки обозначены отдельным более тёмным красным и текстом.

Тёмная тема: глубокие чернильно-ягодные поверхности без коричневого оттенка, светлый текст и яркий ягодный акцент вместо персикового. Это отдельная палитра, не filter/invert. Поверхности не должны превращаться в набор розовых блоков.

`tokens.css` — единственный источник значений; цвета объявлены в OKLCH. Светлые токены в `:root`, тёмные переопределения в `[data-theme='dark']`. Компоненты используют токены по роли. Для опасных действий есть собственные `--color-error`, `--color-error-hover` и `--color-error-ink`; они не зависят от цвета текста основной кнопки.

## Типографика и размеры

- Golos Text — одна локальная гарнитура с кириллицей для всего интерфейса и логотипа; variable font 400–900, используются веса 400/600/700. Файл `docs/design/assets/golos-text-variable.ttf`, лицензия `Golos-Text-OFL.txt`. Не возвращать книжный Garamond в логотип или технический Plex в текст. Старые файлы шрифтов не загружаются новым CSS.
- Заголовки экранов 28–32 px, названия списков и желаний 20 px, текст 16 px, метаданные и вспомогательный интерфейс 14 px. Подписи пульта прототипа — 12 px. Заголовки прямые, без italic.
- Длинные названия списков переносятся целиком. Имя в шапке ограничено 12 rem и сокращается многоточием только визуально; полный текст сохраняется в DOM и в форме аккаунта.
- Контент до 1120 px вместе с внутренними отступами: 24 px на телефоне, 32 на планшете, 48 на desktop. Шкала отступов основана на 4 px.

## Компоненты

- Главная кнопка — сплошная акцентная, вторичная — светлая контурная, служебная — без рамки и заливки. Опасное подтверждение — отдельная красная кнопка; hover не превращает его в обычное действие.
- Поля и основные кнопки имеют базовую высоту 48 px; небольшие кнопки и icon actions — 44 px. Radius 8 px. «Поделиться» не конкурирует с «Добавить желание». Повторяющееся «Я подарю» — контурное действие с иконкой подарка, не сплошная красная кнопка и не на всю ширину.
- Образцы восьми состояний используют один вариант основной кнопки. Сетка образцов учитывает фактическую ширину кнопки и не сжимает подпись «Сохранено».
- Высокий приоритет выделен цветом и звездой, остальные обозначены спокойным текстом. Приоритет не предшествует названию желания. Пояснение приватности — одна обычная фраза с иконкой, без цветного блока и слогана. Название вишлиста и описание предшествуют дате и доступу.
- Skeleton загрузки повторяет строки коллекции, а не удалённые обложки. Нет мерцания и анимации ради анимации.
- Служебные действия владельца находятся в меню с кнопкой «…»: изменить, снять существующую бронь, удалить. У посетителя этих меню нет; его главный путь — выбрать подарок.
- Меню использует Popover API — встроенные всплывающие панели браузера с закрытием по Escape и нажатию снаружи. Это группа обычных кнопок, не `role=menu`: Tab последовательно обходит действия. При недостатке места меню раскрывается вверх; после изменения размера окна или настоящей прокрутки закрывается.
- После сохранения фокус возвращается к кнопке меню в обновлённом DOM; после удаления желания — к main. Кольцо фокуса внутри панели не обрезается её границами.
- Целые цены показываются без нулевых копеек, дробные — с двумя знаками. Это форматирование вывода, не изменение суммы или валюты. Денежная модель и ограничения API остаются отдельным контрактом.
- Пометки о roadmap, этапах разработки и API-контрактах находятся в `HANDOFF.md`, а не внутри потребительских форм. Демонстрационный характер и отсутствие API обозначены в пульте прототипа.
- У посетителя свободное желание сразу предлагает «Я подарю»: отдельный статус «Можно подарить» не повторяется. Чужая бронь показана текстом без дублирующей disabled-кнопки; своя — текстом и действием отмены. У владельца сохраняется статус каждого желания. Посетителю не нужен дополнительный заголовок «Желания» перед уже подписанным списком.
- Подвала со служебными ссылками внутри пользовательских экранов нет. Компоненты доступны через пульт, спецификация — через ссылку в нём. Сортировка коллекции выровнена по началу списка, а не висит отдельно справа.
- Нет рекламных баннеров, повторяющихся слоганов, декоративных иконок навигации, градиентов и анимированных украшений. Единственная тень — у настоящего всплывающего меню, чтобы отделить панель от содержимого под ней.
- Движение: нажатие кнопки и появление диалога. Цвет текста и заливка переключаются одновременно, без промежуточного нечитаемого кадра при смене темы. Reduced motion отключает переходы. Фокус возникает сразу; программный фокус main не обводит весь экран.

## Тема и продуктовые инварианты

`docs/design/theme.js` до CSS применяет сохранённый выбор или `prefers-color-scheme`. «По системе / Светлая / Тёмная» доступны на каждом экране. В storage хранится только `wishlist-design-theme`; запрет storage не ломает выбор темы. Переключение темы не пересоздаёт форму, диалог или продуктовые данные.

Маршруты и сценарии сохранены. Личность дарителя скрыта от владельца и других посетителей; у брони нет таймера истечения. Свет и тьма не меняют права и смысл статусов.

## Передача в разработку

Эта система + `docs/design/HANDOFF.md` + HTML/CSS/JS и 20 PNG в `docs/design/previews/`, включая два открытых меню. Ресурсы текущего пакета помечены версией `quiet-gifts-4`, чтобы не смешивать старый CSS и JavaScript с новыми токенами. Это прототип без API. Не переносить демо-данные, пульт сценариев и in-memory модель как production архитектуру. Бэкенд и принятые спецификации редизайном не меняются.

## Exports

### tokens.css

Полный источник цветов, шрифтов, размеров и обеих тем — корневой `tokens.css`. Прототип импортирует его в `docs/design/styles.css`; отдельные копии палитры не нужны. При переносе сначала подключить этот файл, затем адаптер выбранной библиотеки.

### Tailwind v4 `@theme`

Адаптер основных ролей; `inline` сохраняет разрешение ссылок на токены текущей темы.

```css
@theme inline {
  --color-background: var(--color-paper);
  --color-foreground: var(--color-ink);
  --color-card: var(--color-surface);
  --color-primary: var(--color-accent);
  --color-primary-foreground: var(--color-accent-ink);
  --color-secondary: var(--color-paper-2);
  --color-muted-foreground: var(--color-muted);
  --color-border: var(--color-rule);
  --color-input: var(--color-control);
  --color-ring: var(--color-focus);
  --color-destructive: var(--color-error);
  --font-sans: var(--font-body);
  --spacing-page: var(--space-lg);
  --text-page-title: var(--text-display);
  --radius-control: var(--radius-input);
}
```

### DTCG `tokens.json`

Основные цветовые роли для импорта в инструменты дизайна. Объект `$type: color` хранит компоненты OKLCH; свет и тьма экспортируются отдельными группами.

```json
{
  "light": {
    "$type": "color",
    "paper": {
      "$value": { "colorSpace": "oklch", "components": [0.99, 0.005, 55] }
    },
    "ink": {
      "$value": { "colorSpace": "oklch", "components": [0.25, 0.015, 350] }
    },
    "muted": {
      "$value": { "colorSpace": "oklch", "components": [0.47, 0.015, 350] }
    },
    "accent": {
      "$value": { "colorSpace": "oklch", "components": [0.56, 0.205, 20] }
    },
    "accent-ink": { "$value": "{light.paper}" }
  },
  "dark": {
    "$type": "color",
    "paper": {
      "$value": { "colorSpace": "oklch", "components": [0.2, 0.012, 335] }
    },
    "ink": {
      "$value": { "colorSpace": "oklch", "components": [0.96, 0.008, 10] }
    },
    "muted": {
      "$value": { "colorSpace": "oklch", "components": [0.77, 0.018, 335] }
    },
    "accent": {
      "$value": { "colorSpace": "oklch", "components": [0.77, 0.145, 12] }
    },
    "accent-ink": {
      "$value": { "colorSpace": "oklch", "components": [0.23, 0.045, 12] }
    }
  },
  "font": {
    "body": {
      "$type": "fontFamily",
      "$value": ["Wishlist Golos", "Segoe UI", "sans-serif"]
    },
    "display": { "$type": "fontFamily", "$value": "{font.body}" }
  },
  "radius": {
    "control": { "$type": "dimension", "$value": { "value": 8, "unit": "px" } }
  }
}
```

### shadcn/ui CSS variables

Адаптер использует полные CSS-цвета, не тройки каналов для `hsl()`. Подключать после `tokens.css`; `.dark` или системный переключатель должны выставлять `data-theme="dark"` на корневом элементе.

```css
:root {
  --background: var(--color-paper);
  --foreground: var(--color-ink);
  --card: var(--color-surface);
  --card-foreground: var(--color-ink);
  --popover: var(--color-surface);
  --popover-foreground: var(--color-ink);
  --primary: var(--color-accent);
  --primary-foreground: var(--color-accent-ink);
  --secondary: var(--color-paper-2);
  --secondary-foreground: var(--color-ink);
  --muted: var(--color-paper-2);
  --muted-foreground: var(--color-muted);
  --accent: var(--color-paper-3);
  --accent-foreground: var(--color-ink);
  --destructive: var(--color-error);
  --destructive-foreground: var(--color-error-ink);
  --border: var(--color-rule);
  --input: var(--color-control);
  --ring: var(--color-focus);
  --radius: var(--radius-input);
}
```
